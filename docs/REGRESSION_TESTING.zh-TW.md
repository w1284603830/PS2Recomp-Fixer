# 完整回歸與依結果修正

[English](REGRESSION_TESTING.md) · [移植與配置](GAME_PORTING.md) · [歷史建置結果](../BUILD_VERIFICATION.md)

本流程整理新鬼武者（Dawn of Dreams）與鬼武者 3 的交接方法，供每個遊戲／版本自行建立測試計畫。
這是操作規範，不是兩個遊戲已全數通過的宣告。編譯成功、靜態入口完整、房間巡檢、實際遊玩、畫面／聲音驗收
是不同層級；任何一層都不能代替其他層。原版模式與高清／寬螢幕等增強模式必須分開記錄。

## 1. 先固定比較基準

每輪記錄基底／候選 commit、遊戲及區域版本、ELF／映像辨識、實際執行的 EXE／GS DLL 雜湊、工具鏈、
相依版本、遊戲 profile、解析度／倍率／比例、渲染與 VU 後端、原版／增強模式。基準與候選使用相同的起始
存檔副本、劇情狀態和已確認被遊戲消費的輸入；保留原始存檔及設定。建置目錄裡的檔案不等於實際啟動的檔案。

使用獨立候選目錄，核對 EXE、DLL、資源與設定是否來自同一輪；不要混用新源碼、舊執行檔和另一版本 DLL。
重啟後也要核對實際掛載的映像與已啟用配置。地址／ABI 配置在成功 `loadELF` 後套用，詳見移植文件。

## 2. 先過基底與重編譯完整性檢查

在庫根目錄執行：

```sh
python -m unittest discover -s tests -v
```

Windows 完整建置與內附測試：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File fetch_deps.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File build_all.ps1
```

首次或相依缺失時才需抓相依。檢查每個測試的實際結果；`-NoTests`、只有成功 exit code、只有測試總數，
都不是完整驗證。這份建置腳本直接執行主測試、IOP 測試與 GS cache 的各測試名稱；單獨跑 CTest 若找到
零個測試，不算通過。歷史已知差異須逐項對照當前 `BUILD_VERIFICATION.md` 的理由，不能用「允許固定失敗
數量」吞掉新失敗，也不能把舊 Windows 結果套到新的源碼。

主 ELF／overlay 函式表有變時，輸出到新目錄，保留 runner 與手寫掛鉤，以庫內的保留式／增量同步工具
同步，再合併該移植所需的註冊及 overlay。重新產生後，核對主 ELF、overlay、跨 overlay 直接呼叫與間接
回呼入口、載入／重定位和缺失目標記錄。鬼武者 3 交接的 `entry_coverage.py`、巡檢與 runner 產生器屬於
該移植的工具，**本庫不附帶它們**；其他移植需自行提供等效檢查。入口掃描零缺失僅代表該靜態規則未發現
缺口，不代表動態回呼全部執行或遊戲通關。

## 3. 從自然流程建立完整矩陣

先跑冷啟動 → 記憶卡／標題 → 選單 → 新遊戲／讀檔 → 場景 → 移動 → 戰鬥 → 切場 → 返回選單。
確認測試按鍵真的被遊戲消費、場景及動作確實改變，再擴展成內容清單。每個房間、事件、影片和存檔案例
要有獨立結果；完整回歸包括主線各章節、Boss、過場、結局與可適用的二周目，不只是開場或數個抽樣房間。

| 路徑 | 需要覆蓋 | 判讀重點 |
|---|---|---|
| EE／overlay／劇情 | 冷啟動、正常讀檔、依攻略連續進房、章節與 Boss、事件逐段及自然連播 | 缺函式、錯誤重定位、事件起訖、角色／鏡頭狀態；強制跳房不等於正常進房 |
| GS／VIF／VU | 原生倍率與高倍率、4:3／16:9、視窗／全螢幕、HUD／字型／選單、粒子、深度／混合、RT／鏡像／後處理 | 固定狀態對照；核對目標 draw 確實進入候選路徑及未受影響的 UI |
| GS 橋接 | 暫存器、VRAM、傳輸／讀回、SIGNAL／FINISH／LABEL、呈現順序與時序 | 找第一個不同的封包／狀態；不能只看最終截圖或平均 FPS |
| 音訊／SPU2 | 音樂、音效、語音、兩個 core、reverb、DMA／AutoDMA、冷／暖載入與長時間播放 | 聲道、音量、時鐘、欠載／丟棄、同步與實際對聽；單次零計數不是全遊戲保證 |
| IOP／SIF／光碟 | 模組載入、RPC／DMA／中斷、讀取／EOF、正常切場與換碟 | guest 進度與音訊時鐘是否合理；不得靠無限超前或跳過回呼掩蓋停頓 |
| IPU／CG／靜圖 | 全片播放、早／晚跳過、連播、播畢回遊戲、字幕／音訊、開場標誌／警告靜圖 | 完成與返回都要驗證；高清 on/off、替代素材缺失時的原生路徑各自測 |
| 記憶卡／設定／輸入 | 副本卡的新建、儲存、退出重開後原生讀檔、進度／裝備、日期／字幕、選單開關、鍵盤／手把 | 不以直接改 RAM 代替原生存讀檔；不把測試存檔混入發佈包 |
| 效能與穩定性 | 使用者常用倍率與輸出、冷／暖載入、長時間切場／戰鬥 | 分辨 guest／host／GS 幀率、frame pacing、I/O 停頓與測試負載 |

### 新鬼武者的提醒

沿自然遊玩路徑檢查移動、戰鬥、選單、換房與章節事件，再跑房間和影片清單。雙碟移植必須測各碟資料，
實際換碟、換碟後的讀取／影片／劇情返回；若支援合併映像，也要單獨測該模式。舊的房間／影片巡檢證據
不能替代未覆蓋的章節、Boss、存讀檔、結局或二周目。原生素材、高清影片與寬螢幕配置各有自己的結果。

### 鬼武者 3 的提醒

依該版本的房間／CG／事件清單，做房間巡檢、影片完整播放、事件逐段與連播，然後以真實進度連續走訪。
部分場景沿用前一場景的 overlay，後段事件依賴前段建立的演員、鏡頭和劇情旗標；從標題強制跳入或單獨
呼叫後段事件，可能製造無效指標。必須從相鄰場景或適當存檔自然進入後再判定原因，不能先把空回呼改成
成功返回。實際戰鬥、角色／武器／裝備／法術等目標效果需真的觸發；資源存在或普通攻擊成功不代表全部
動作／素材已驗收。各版本及原版／增強模式仍要獨立驗證。

兩作只是方法來源，測試房號、地址、腳本名稱、場次與耗時都不是其他遊戲可套用的常數。粒子修正亦適用
此規則：**每個遊戲／修訂版都需獨立 profile 與畫面驗證，包括兩個參考遊戲。**

## 4. 從回歸失敗定位與修正

1. **先重現並分流。** 固定源碼、二進位、配置、存檔與輸入，保存故障案例。分清真實功能失敗、未觸發、
   前置狀態不成立、工具判定問題與資源爭用。音訊／效能與時序對照先用單實例；並行壓力下的卡死或欠載，
   以低負載重跑失敗案例確認，不直接以假設改遊戲。未重現或原因未證實要照實記錄。
2. **找第一個差異。** 原生參考／已驗證基準與重編譯候選固定同一狀態；沿 EE → VIF／VU → GIF → GS
   比較暫存器、記憶體、封包、draw 與時序。CPU 光柵器可作其已支援路徑的輔助對照，不能視為涵蓋所有 GS
   行為的真值。保留第一個分歧的 PC／RA／overlay 與相關輸入，不只修最後看到的症狀。
3. **區分測試與內容。** 音訊尖刺／靜音要核對實際來源、格式版本與對應解碼／播放參考，不以單一解碼器
   輸出不同就判移植錯誤。畫面缺物件先查劇情及素材載入；檔案安裝、profile 啟用、路徑被執行與人眼接受
   是四種證據。逐 pixel 比較需對齊相同 frame／field／狀態；相鄰幀 A/B 可含動畫與 RT 差異，必要時用凍結重播。
4. **修正所屬層。** 硬體語義或共用機制以硬體／上游依據和最小重現支持；地址、SDK ABI、HPO／粒子篩選、
   圖集／字幕／素材規則留在遊戲 profile。不得為消除報錯而跳過 draw／事件、假裝回呼成功或把測試例外全域化。
5. **加入有意義的回歸案例。** 覆蓋原失敗及直接相關邊界，例如錯版本拒絕、地址範圍、overlay 切換、回呼
   連續完成、profile 重開清除、原版／增強切換；斷言觀察到的行為，不只是重複實作中的判斷式。
6. **建置同一候選後重測。** 統一受影響的 runtime／runner／GS 與配置，核對執行檔雜湊，重跑原失敗案例、
   相鄰路徑及必要基底測試。修改生成碼流程時重做入口檢查。日常修正先做定向回歸；驗收候選再依受影響
   範圍與發佈目標跑完整矩陣，不為每個局部修正反覆重跑未受影響且證據有效的全清單。
7. **實看／實聽並關閉證據鏈。** 檢查必要畫面、連續播放與操作結果，記錄未解決問題及未測範圍。通過後
   才把該候選列為驗收版本；部署後以實際入口做啟動／版本核對，不以 build 輸出代替部署結果。

## 5. 每個案例都留下可稽核結果

| 欄位 | 內容 |
|---|---|
| 案例及範圍 | 遊戲／修訂版、模式、房間／事件／影片／存檔案例、預期結果 |
| 基準及候選 | commit、EXE／DLL 雜湊、映像辨識、profile、工具版本、啟動參數 |
| 可重現輸入 | 起始狀態／存檔副本、被消費的按鍵、自然進入或強制掛鉤、負載條件 |
| 路徑證據 | 入口／overlay、目標 draw 或 DMA／回呼、音訊計數／時鐘、必要影像與日誌 |
| 結果 | `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`；不適用須寫明原因 |
| 驗收邊界 | 自動判定、人工實看／對聽各自的結果；後續修正與重測版本 |

未觸發、空 draw、零個測試、未播畢、缺有效前置狀態與未實看／對聽，不可改記 PASS。保留失敗與後續修正
的對應，不刪除失敗以湊全綠；只改判定器而未重跑時，也須標明重新判讀的是哪份原始結果。保留必要的
版本、摘要與經允許保存的診斷證據；原始遊戲／素材／存檔不隨報告上傳公開庫。測試計畫不代表已執行，
舊交接中的控制器、排程、清理與部署動作也不會因閱讀本文件而自動重啟。
