# 對 PS2Recomp（eb8688b）的修改

所有修改都在 `third_party/src/PS2Recomp/` 工作樹，程式碼註解以 `[DoD]` 標記。原版可由 `third_party/_downloads/PS2Recomp-eb8688b.zip` 還原比對。

## 綁定調整

- 2026-10-18（codex105）：`sceGsSyncV` 改讀原版 `sceGsGetGParam` 回傳的 16-bit inter 與 intcUsed，保留原版完成時讀 inter、VSync live FIELD 與 VSync2 wake FIELD 語義。只修該 HLE，不改 scheduler 通用 parity。新實作19/19測試通過，修前同組9項失敗；見 `work/codex-boot-20261018/gs-syncv-tests/README.md`。
- 2026-10-18（codex103／104）：補上 DBCMAN 使用的 IOP sifman ordinal32 `sceSifSetDmaIntr`，與 ordinal7 共用經驗證的 descriptor 複製，成功後排入既有 guest callback 執行器呼叫原版 completion（含 iSignalSema），不直接改 semaphore 或遊戲狀態。10/10隔離測試通過。真實鍵盤→SIO2→原版 DMA→EE 按鍵邊緣已實跑驗證。
- 2026-10-18：raylib 輸入集中視窗執行緒，IOP/EE 讀 mutex snapshot；短按事件保留至有效普通0x42取樣，並保留同一 host publication 的狀態。相關隔離測試730,149 assertions 通過；原版主迴圈實際取樣仍需另量測，不把 SIO2 收到事件視為遊戲一定處理。
- 2026-10-18：新增 opt-in DOD_PERF 與 bounded pad trace；host 使用 atomic GS VBlank counter，正常 GS latch 不再二次取得無用途的 debug-history 鎖。純 callback carrier 的負 thread id 結束屬正常，不再輸出通用「thread returned to pc0」誤導診斷；正 thread 診斷保留。

- 2026-10-18（codex99 驗證）：在 LoadImage 兩函式之外，一致恢復 ResetGraph、SetDefDispEnv、zbufaddr、SetDefDrawEnv/2、SetDefClear、PutDrawEnv、SetDefDBuff/Dc 九個原碼函式。修正原版 global 與 HLE 私有參數脫節、錯誤的 buffer 指派、清屏 no-op、完整 GIF 封包被當作裸 A+D pair 等問題。PMODE 已從 `0x8007` 變成原版 `0x66`，DISPLAY2 與 PCSX2 同為 `0x001BF9FF0203227C`。SyncV／SyncPath／callback HLE 保留；原版 IMR 初始化與遊戲後續解遮罩已靜態核對。
- 2026-10-18（codex100 畫面驗證）：`gs_cpu_backend.cpp` 解碼 DISPLAY 的 MAGV，僅在 SMODE2 的 INT=1、FFMD=1 時將來源高度向上取整除2。NTSC 本遊戲應讀512×224連續列，再呈現成4:3；原本錯讀448列導致畫面下半出現別的 VRAM 資料。DBY、列步進與另一種 FIELD 模式維持原本語意。證據見 `GS_FFMD_SCANOUT_REVIEW.md` 及 `dist/logs/codex100-ffmd-pad/present/`。

- 2026-10-18：`dod_native_libgraph.toml` 移除 `sceGsSetDefLoadImage@0x1037D0`、`sceGsExecLoadImage@0x1039B8` 的 HLE 綁定。原 HLE 使用 12-byte `GsImageMem`，原版則建立 96-byte／6 QW 的 GIF setup，最後一個 QW 為 IMAGE tag。原 MIPS、ICO `sce/libgraph/graph015.c` 與 PCSX2 記憶體取樣三方一致；兩邊 0x734920 的 131072-byte 像素 SHA256 同為 `b257f00fcb5132bec261ebfc83ecf9bf82e107babb4b49f18c1515bcddd4db03`，所以未修改像素解碼。兩個 SDK 函式一起恢復原碼，避免 ExecLoadImage 繼續讀取錯誤結構。
